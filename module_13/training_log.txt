Why train/test separation matters:
Train/test separation matters because it is the only way to estimate how the model will perform on data it has never seen. A model can always fit its training data well by memorizing patterns specific to those examples.The test set is what tells us whether it has learned something that generalizes, versus just memorized entries. This is critical when the trained model will be deployed on a public-facing webpage ('Will You Get In?'). Every real user who submits via the form is, by definition, a case the model has never seen during training. If we evaluated only on training data, we would have no honest way to know how the model will perform for live users. We would be reporting how well it memorized the past, not how reliable its predictions will be for someone using the site tomorrow.

Interpretation:
- Bias: The model recalls Rejected applicants (85.6%) better than Accepted applicants (71.2%), predicting Accepted 3131 times vs. 3519 actual Accepted cases in the test set. This suggests some bias toward predicting the majority class (Rejected).
- Vs. random/majority guessing: The majority-class baseline (always predicting the more common outcome in the test set) would score 55.2% accuracy. The fine-tuned model scores 79.1%, which is meaningfully above this baseline, indicating it has learned real signal beyond guessing the majority class.
- Vs. earlier two-layer NN: The two-layer NumPy NN scored 70.0% test accuracy; the fine-tuned transformer scores 79.1%, an improvement, consistent with the transformer being able to use free-text fields (Comments, Program, University) that the purely numeric NN could not.
- Dataset sufficiency: Only about 20% of GPA/GRE fields are populated on average in this test set (many applicants don't report them), and labels come from self-reported, unverified GradCafe outcomes with no information on program competitiveness, applicant pool size, or redacted comment content (~12% of comments needed outcome-language redaction, per Step 2). That's enough signal to beat a naive majority-class guess, but it falls well short of what a real admissions office would need: no verified transcripts, no letters of recommendation, no interview data, and no guarantee the sample is representative of any single program's applicant pool. This model is a reasonable course-project demonstration of text+tabular fine-tuning, not a realistic admissions predictor.
